# Releasing ez-pocket

## Current Windows release status

GitHub Actions builds and tests the Windows target on pull requests and `main`.
Pushing a version tag such as `v0.1.0` also produces an **unsigned** x64 MSIX artifact. It is retained for 14 days for maintainer testing and eventual signing; it must not be published as the normal public download.

## Why an unsigned package is not a public release

Windows does not trust an unsigned MSIX package. A self-signed package is suitable only for machines where the recipient has manually installed the publisher certificate. Neither option is appropriate for ordinary GitHub Release downloads.

The intended public-release route is SignPath Foundation, provided ez-pocket meets its open-source eligibility and code-signing-policy requirements. SignPath will sign the MSIX generated by CI with a publicly trusted certificate. Do not upload a package to a public GitHub Release until that signing step has completed and the signature has been verified.

## Pre-signing release checklist

1. Update `ApplicationDisplayVersion` and `ApplicationVersion` in `EzPocket.csproj`.
2. Update the MSIX four-part version in `Platforms/Windows/Package.appxmanifest`.
3. Build and test the Windows target locally.
4. Commit the version changes, then tag that commit as `v<display-version>`.
5. Confirm the tag workflow uploaded the unsigned MSIX artifact.

## After SignPath is configured

1. Send only the CI-produced MSIX package through the approved SignPath workflow.
2. Verify the signed result on a clean Windows machine using `Get-AuthenticodeSignature`.
3. Attach the signed MSIX, a SHA-256 checksum, release notes, and an install/update guide to the GitHub Release.
4. Never publish the unsigned artifact or a self-signed certificate as the primary release download.

## Package identity

The Windows package identity is `Bitbird.EzPocket`, with publisher `CN=Bitbird`. The package publisher must remain aligned with the eventual trusted signing identity for upgrades to work correctly.
